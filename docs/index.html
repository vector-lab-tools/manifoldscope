01 · About

What Manifoldscope does.

Manifoldscope loads a single embedding manifold — the output vectors of one model under one sample — and runs two kinds of operation against it. Every finding carries a provenance record (manifold source, sample, metric, projection, probe list, parameters) so that results can be reproduced and cited.

Measure

Geometry

Intrinsic dimension, Forman-Ricci curvature, density gradient, geodesic map, sampling-bias, persistent homology, projection-distortion grid.

Critique

Ideology

Ideological topography, hegemonic gravity, market colonisation, normative transition, dissensus detector, grammatical ideology, training-data fingerprinting, temporal sedimentation, synonymic erosion, metric archaeology.

Atlas

Curated runs

Pre-computed analyses on named samples, bundled with provenance and annotations. Ships in Phase 4.

02 · Install

Installing it locally.

Prerequisites

  • Python 3.11+ for the FastAPI backend.
  • Node.js 18+ (20 LTS recommended) and npm.
  • Git, to clone the repository.
  • For the default local embedder, nothing further: Manifoldscope ships with sentence-transformers and runs MiniLM out of the box. For other providers see API keys.

Clone and install

git clone https://github.com/vector-lab-tools/manifoldscope.git
cd manifoldscope
npm install
cd backend
./setup.sh

setup.sh creates backend/.venv and installs FastAPI, scikit-learn, numpy, scipy, networkx, ripser, and the rest.

Run

Backend, in one terminal:

cd backend
source .venv/bin/activate
uvicorn main:app --reload --port 8000

Frontend, in a second terminal:

npm run dev

Open http://localhost:3000. The default sample (Philosophy of Technology concept list) loads automatically. Click Measure → Intrinsic Dimension → Run for a first result.

If the header shows "Backend offline". The frontend is up but the FastAPI server on port 8000 is not reachable. Check the backend terminal for a stack trace, then confirm with curl http://localhost:8000/status.
03 · Use

Running your first operation.

  1. Open localhost:3000. The sample loader at the top picks the default Philosophy of Technology concept list.
  2. Stay on the Measure tab, with Intrinsic Dimension selected.
  3. Click Run. The backend embeds the sample under the configured provider, estimates per-point TwoNN local dimension, and streams the result back as NDJSON. The scatter colours each concept by its local dimension; the Deep Dive panel reports the quantitative breakdown.
  4. Switch to Critique, pick Ideological Topography, and run again. The result renders alongside the Measure attestation that was computed on the same sample.

Swap the sample

The sample loader accepts a concept list (plain text, one concept per line), a Zotero export, a Vectorscope hidden-state export, or a Theoryscope corpus-map import. Every operation records which sample it ran against; two runs on different samples never share a provenance record.

Swap the provider

The default is a local sentence-transformers model (no key, no quota). To switch to a hosted embedding model, see the next section.

04 · API keys

Getting the API keys working.

Hosted embedding providers all work the same way at a high level: register, create a key, paste the key into Manifoldscope's provider settings, pick a model. Each card below gives the key source, the key prefix, cost tier, and the one gotcha that bites first.

Keys are stored locally. Manifoldscope keeps provider keys in your browser (IndexedDB). Keys are never sent to the Vector Lab or to any third party; the only outbound call carrying a key is the direct request to that provider's embedding endpoint. Clearing site data for localhost:3000 removes them.
Current build. Phases 0–2a ship with the local sentence-transformers embedder enabled by default. The in-app provider-settings panel for hosted keys lands with Phase 2b. The procedures below are correct for key creation now; the paste step unlocks when 2b lands. Meanwhile, Ollama (below) runs locally and needs no key.

OpenAI

Paid

platform.openai.com/api-keys → sk-…

text-embedding-3-large (3072d) · text-embedding-3-small (1536d)

Gotcha: a payment method is required before any call, including the first test. New accounts also default to a $0 spend cap — raise it at Billing → Limits.

Voyage AI

Free tier

dash.voyageai.com → API Keys → pa-…

voyage-3.5 · voyage-3-large · voyage-3 (all 1024d)

Gotcha: 50M tokens / month free across all keys on the account — not per key.

Google (AI Studio)

Free tier

aistudio.google.com → Get API key → AIza…

gemini-embedding-001 (3072d, Matryoshka-truncatable)

Gotcha: use AI Studio, not Vertex. The key pins to a hidden GCP project; if it suddenly says "API key not valid", the project was auto-reaped — create a new key.

Cohere

Free tier

dashboard.cohere.com → API Keys

embed-v4.0 · embed-v3.0 (1024d)

Gotcha: the default key is a Trial key, rate-limited and non-commercial. A Production key requires a payment method.

HuggingFace

Free

huggingface.co/settings/tokens → New token → hf_…

Any embedding model via the Inference API, e.g. BAAI/bge-small-en-v1.5 (384d), mixedbread-ai/mxbai-embed-large-v1, intfloat/multilingual-e5-large, Qwen/Qwen3-Embedding-0.6B (1024d)

Gotcha: first request to a model cold-starts it (30–60s). Second call is fast. Pick a popular model to minimise cold starts, or switch to Ollama.

sentence-transformers

Local

built in · nothing to configure

Default: sentence-transformers/all-MiniLM-L6-v2 (384d). First run downloads ~90 MB to ~/.cache/huggingface/.

Other models: click Model in the app header and type any sentence-transformers or Hugging Face model id. Blank fields, or Clear to defaults then Save, return to MiniLM. The backend default can also be set with MANIFOLDSCOPE_MODEL_ID.

Local provider · Ollama Local

Ollama runs embedding models on your own CPU or GPU. No key, no network, no quota. This is the recommended path for offline work.

  1. Install Ollama from ollama.com/download.
  2. Pull an embedding model: 
    ollama pull nomic-embed-text    # 768d, fast
ollama pull mxbai-embed-large   # 1024d, better quality
ollama pull embeddinggemma      # 768d, Google
  3. Allow the browser to call Ollama from localhost:3000: 
    launchctl setenv OLLAMA_ORIGINS "http://localhost:3000"
# restart Ollama (menubar icon → Quit, then relaunch)

    On Linux: add Environment="OLLAMA_ORIGINS=http://localhost:3000" to ~/.config/systemd/user/ollama.service.d/override.conf then systemctl --user restart ollama.

  4. Confirm Ollama is reachable: curl http://localhost:11434/api/tags should return the model list.
  5. In Manifoldscope, open Settings → Providers → Ollama, leave the key blank, enter the model name (e.g. nomic-embed-text).
Safari users: Safari blocks mixed-origin calls from an https page to a plain http://localhost endpoint, and sometimes blocks them from http://localhost too. If Ollama requests silently fail in Safari, use Chrome or Firefox, or run Manifoldscope from http://127.0.0.1:3000 (Safari treats this origin differently).

Which provider for which operation

  • Measure operations work with any provider. For reproducible open-weight geometry, prefer sentence-transformers or Ollama.
  • Critique operations that bind geometry to training provenance (Training-Data Fingerprinting, Synonymic Erosion, Metric Archaeology) prefer open-weight backbones so model internals can be inspected. Commercial APIs will run them, but the archaeological reading is weaker.
  • Metric Archaeology needs two embedders at once; MiniLM and MPNet are the defaults.
05 · Examples

Three worked examples.

1. A philosophy-of-technology sample under OpenAI vs MiniLM

  1. Load the default sample.
  2. Configure OpenAI as above. Run Measure → Intrinsic Dimension; note the mean local ID.
  3. Switch to the built-in sentence-transformers provider. Run the same operation again.
  4. Open Measure → Metric Archaeology. The two embedders Procrustes-align with a quantified residual; the Jaccard overlap of each concept's k-NN tells you where the two models disagree about who neighbours whom.

2. Ideology under a known axis

  1. Open Critique → Ideological Topography. The default probe gives five contested axes (freedom/control, labour/capital, nature/culture, individual/collective, universal/particular).
  2. Run against the Philosophy of Technology sample. Each concept is scored on each axis; the heatmap colours each region by its net lean.
  3. The Measure attestation card next to the result shows the intrinsic dimension and curvature of the same sample under the same embedder, so you can read the ideological pattern against the geometric one.

3. Market colonisation of a technical vocabulary

  1. Switch to a sample of your own — e.g. an export from your Zotero collection of AI-ethics abstracts.
  2. Open Critique → Market-Colonisation Index. The probe lists market vocabulary (customer, product, market, return, asset, liability, …).
  3. The gradient field shows how market vocabulary is distributed across your sample's manifold; the per-concept score ranks which of your concepts have been pulled closest to the market pole.
06 · Troubleshooting

When something goes wrong.

"Backend offline" in the header

The frontend cannot reach http://localhost:8000. Check the backend terminal, then curl http://localhost:8000/status. If the backend is running on a different host or port, set MANIFOLDSCOPE_BACKEND_URL before npm run dev.

"ModuleNotFoundError: No module named 'ripser'"

Ripser needs a working C compiler. On macOS: xcode-select --install. On Debian/Ubuntu: apt install build-essential. Then re-run ./setup.sh.

HuggingFace times out on the first call

Cold start. Re-run; the second call lands on a warm instance. If the model is routinely cold, pick a more popular one (e.g. sentence-transformers/all-MiniLM-L6-v2) or switch to Ollama.

The Run button is disabled

No sample loaded or no provider configured. The status bar at the bottom of the window reports which of the two is missing.

07 · FAQ

Questions about the project.

When was Manifoldscope first created?

Built at Copenhagen Business School, Denmark, during an Otto Mønsted Visiting Professorship in 2026. The support of the Otto Mønsted Fond (grant 25-12-1849) is gratefully acknowledged.

Development began on 17 April 2026. The first commit set out the concept in a README, and the same day brought the Phase 0 scaffold: the Measure, Critique and Atlas tabs, the provenance record that every result carries, and the first two operations, Intrinsic Dimension Field and the Market-Colonisation Index.

How has it developed since then?

The operations came first, in phases, over one week in April 2026:

  • 17 April: Phase 0, then Phase 1a (Curvature Estimation, Density Gradient Field, Geodesic Map, Sampling-Bias Diagnostic) and Phase 1b (Ideological Topography, Hegemonic Gravity Map, Normative Transition Probe).
  • 22 April: Void Atlas and the Projection-Distortion Meter on the Measure side; the Dissensus Detector and the Grammatical Ideology Probe on the Critique side.
  • 23 April: Phase 2a, the archaeological and forensic operations: Training-Data Fingerprinting, Temporal Sedimentation, Synonymic Erosion and Metric Archaeology (v0.4.0).

Later work concerned the instrument as a publication:

  • 13 June 2026: v0.4.1 adopted the shared Vector Lab branding.
  • 9 August 2026: v0.5.0 moved the licence from MIT to GPL-3.0-or-later, covering all earlier versions.
  • 27 October 2026: this documentation site went up, and v0.5.1 became the first release archived at Zenodo with a DOI.
  • 29 October 2026: v0.5.2 added a citation file with the author's ORCID iD.
  • 12 November 2026: a free-text model field, so any sentence-transformers or Hugging Face embedding model can be used in place of the default, and this FAQ (v0.5.3).

Still to come, per the roadmap: Phase 2b (subaltern geometry, and the settings panel for hosted-provider keys), Phase 3 (limits, refusals and absences), Phase 4 (interchange with Vectorscope and Theoryscope, a Counter-Reading Layer and Atlas export), and Phase 5, the 1.0 release with curated Atlas entries.

Who made it?

Concept and design by David M. Berry, University of Sussex, implemented with Claude Code. The design system is adapted from the CCS Workbench, and the geometry library, streaming and provenance code are shared with the other Vector Lab instruments.

Where is the source code?

On GitHub at vector-lab-tools/manifoldscope. The releases page lists each version with notes, and the commit history records the development step by step.

How do I report a problem or suggest a change?

If it is not on this page, open an issue on the tool's repository to report the problem. If you have a fix, a pull request is welcome.

Questions that apply to all the Vector Lab tools, such as API keys and local models, are answered in the Vector Lab FAQ.

How do I cite Manifoldscope?

Cite the concept DOI 10.5281/zenodo.23714913, which always resolves to the latest archived release. The repository's "Cite this repository" button on GitHub gives APA and BibTeX versions, and the README has a Harvard reference.

08 · Sibling instruments

The rest of the family.

Manifoldscope is one of five tools in the Vector Lab. They share an editorial design system, an open-weight-friendly methodology, and a provenance plumbing pattern, and differ in their object:

  • Vectorscope — internals of a single open-weight model (hidden states, attention, residual stream).
  • Manifold Atlas — comparison of output geometries across many models.
  • Theoryscope — the geometry of a corpus of theoretical texts.
  • LLMbench — the surface of model outputs read as prose.

See the Vector Lab overview for the map of how they fit together.
